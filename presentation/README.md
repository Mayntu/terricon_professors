# JANA / THE FLOW

Отдельная интерактивная HTML-презентация JanaМен: **3 слайда и отдельный 30-секундный финальный ролик**, React + TypeScript + GSAP. Рабочая сцена 1920×1080 автоматически вписывается в экран с сохранением пропорций.

Презентация не подключается к FastAPI, не отправляет заявки и не меняет данные HR-платформы. Здесь собственные `package.json`, lockfile, Vite и `dist/`. Основной сайт на 5173, API на 8000 и Docker Compose остаются независимыми.

## Запуск на Windows

Нужен Node.js **22.12+**. Откройте отдельный PowerShell:

```powershell
cd D:\projects\janamenhack\terricon_professors\presentation
npm.cmd ci
npm.cmd run dev
```

Открыть **http://localhost:5180**. Установка `npm.cmd ci` нужна при первом запуске или изменении lockfile. Если зависимости уже установлены, достаточно `npm.cmd run dev`.

Backend, PostgreSQL, Docker и ключ Anthropic для презентации не нужны. Основной JanaМен может работать одновременно. Остановка презентации — `Ctrl+C` в её терминале.

Если порт 5180 уже занят предыдущим запуском, откройте существующий адрес или остановите предыдущий процесс. Порт выбран строго: Vite не переключится незаметно на другой адрес.

## Управление

| Клавиша | Действие |
|---|---|
| `→` или `Space` | Следующий слайд |
| `←` | Предыдущий слайд |
| `F` | Включить / выключить fullscreen |
| `Esc` | Выйти из fullscreen; при открытом скриншоте сначала закрыть его |
| `R` | Повторить текущую сцену |
| Кнопки `01 / 02 / 03` | Перейти к нужному слайду |

После третьего слайда кнопка **▷ / «Смотреть финальный ролик»** или `→` запускает финал. Прямой вход: **http://localhost:5180/#outro**. В ролике `Space` — пауза/продолжить, `R` — повтор, `F` — fullscreen, `←` — вернуться к третьему слайду. Есть ползунок времени; после 30 секунд кадр замирает. `Esc` сначала выходит из fullscreen, вне fullscreen возвращает к слайдам. При reduced motion сразу показан статичный финал.

На третьем слайде панели и кнопки `1…7` открывают оригинальные скриншоты крупно. После закрытия фокус возвращается на кнопку. Переходы доступны сразу, ждать вступление не обязательно. Слайды сами не перелистываются.

Ссылка `http://localhost:5180/#slide-3` открывает сразу решение. Для спокойного статичного показа включите системную настройку уменьшения движения: приложение учитывает `prefers-reduced-motion`, включая изменение настройки во время показа.

## Режиссура трёх сцен

**01 / Начало маршрута.** Тёмное поле, координатная сетка, световой сигнал на SVG-маршруте, короткое движение камеры и типографическая маска. Имена: **Бондарев Владислав**, **Хуснуллил Даниил**.

**02 / Разрыв.** Светлая редакционная композиция. Пять отдельных интерфейсных островов и оборванные связи. Это визуальная метафора проблемы, а не утверждение о конкретных пяти установленных системах заказчика. При переходе острова выравниваются и проявляется зелёный маршрут.

**03 / Решение.** За примерно 12 секунд автоматически показываются реальный Dashboard, приближение к области заявки, отпуск, Flow Map, интерфейс руководителя и подтверждённый результат. Затем раскрываются Academy и AI Jana. Финальная композиция остаётся на экране столько, сколько нужно докладчику.

Во всех сценах есть enter, статичный idle и exit. Переход строится на смещении камеры и маске маршрута. GSAP timelines ограничены контекстом сцены, очищаются при переходе и повторе; бесконечных фоновых анимаций нет.

Текст выступления и рекомендуемый темп — [SPEAKER_NOTES.md](SPEAKER_NOTES.md).

Итоговые кадры 1920×1080: [01 — титул](docs/slide-01.png), [02 — проблема](docs/slide-02.png), [03 — решение](docs/slide-03.png).

Маршруты, время и способ съёмки записаны в [provenance.json](public/assets/product/provenance.json). Скрыты только всплывающие уведомления и служебная кнопка DEMO; текст и состояния продукта не перерисованы. В композиции применяется кадрирование, оригиналы можно открыть целиком.

Заявка на рассмотрении и согласованная заявка — **разные существующие тестовые записи**. Их последовательность иллюстрирует процесс, не изображает живое изменение БД. На слайде есть отметка «Снимок демо-среды / не live».

Скрипт `npm.cmd run capture` предназначен только для повторной съёмки подготовленных QA-стендов: по умолчанию `15173/18000` и `15174/18001`. Он не нужен для запуска презентации. Он входит тестовыми пользователями и задаёт AI-вопрос; не сбрасывает данные, не создаёт отпуск и не принимает решение. Эти стенды должны уже содержать нужные записи. Не запускайте скрипт против рабочей базы с реальными сотрудниками.

## Финальный ролик · From Request to Result

[Открыть MP4](output/jana-from-request-to-result.mp4): **1920×1080, 30 FPS, 30 секунд, H.264, без звука**. Его можно воспроизвести обычным видеоплеером без Node.js и основного приложения. Проверены все 900 кадров, точная длительность, отсутствие чёрных кадров, неподвижный финал и воспроизведение файла в Chrome. [Отчёт](output/README.md). MP4 — локальный результат рендера, он исключён из Git; при переносе презентации скопируйте его отдельно или пересоберите.

| Время | Сцена |
|---|---|
| 0–5 с | Авторская 2.5D-фура на цифровой дороге, «У каждого запроса есть путь» |
| 5–10 с | Портал → настоящая форма отпуска → выбранные даты → отправка → сигнал |
| 10–15 с | Employee → Manager → Result; реальное подтверждение руководителя, затем зелёный маршрут |
| 15–20 с | HR-заявки, завершённый курс, AI-ответ и открытый первоисточник |
| 20–25 с | SVG-маршруты собираются в существующий знак JanaМен |
| 25–30 с | «От запроса — к результату», оба автора, один световой импульс и неподвижный финал |

Фура — метафора движения запроса. Ролик показывает обычное согласование руководителем; HR участвует в продукте при эскалации, а не как обязательный узел этого маршрута. Звуковой дорожки нет; всё содержание понятно визуально.

Для ролика отдельно снята **одна** заявка: заполнение, отправка, панель руководителя и сохранённое согласование относятся к одному UUID. Academy показывает реальный ранее сохранённый результат 100%; AI — реальный ответ и доступный документ. [Происхождение кадров](public/assets/outro/provenance.json). Это заранее снятый демонстрационный сценарий, не live-сессия. В отличие от слайдов, отправленная и согласованная заявки здесь не разные записи.

`npm.cmd run capture:outro` **создаёт и согласовывает одну двухдневную заявку на изолированном QA-стенде 15173/18000**, не сбрасывая БД. Для просмотра и рендера эта команда не нужна. Основные 5173/8000 не используются. Кадры и подписи сохраняются локально; показ не вызывает API.

### Пересобрать MP4

Нужны установленные npm-зависимости, Chrome и FFmpeg. Если FFmpeg отсутствует, подготовьте его один раз отдельно от приложения (требуется Python и интернет):

```powershell
cd D:\projects\janamenhack\terricon_professors\presentation
python -m pip install --target .tools imageio-ffmpeg==0.6.0
```

Либо укажите свой исполняемый файл:

```powershell
$env:FFMPEG_PATH = 'C:\tools\ffmpeg\bin\ffmpeg.exe'
```

Рендер запускает собственный preview на свободном порту **5184**, автоматически пересобирает HTML и сохраняет MP4:

```powershell
npm.cmd run render:outro
```

Экспорт не записывает экран в реальном времени. Для кадра `n` общий GSAP timeline ставится на `n / 30`, Playwright получает PNG, FFmpeg кодирует 900 кадров по порядку. Скорость компьютера влияет на время сборки, но не на тайминг видео. Remotion не нужен: HTML и видео используют одни React-компоненты и одну анимацию без второй реализации.

Для быстрой проверки опорных кадров после сборки:

```powershell
npm.cmd run build
node scripts/render-outro.mjs --stills
```

Опорные кадры — `output/storyboard/`, параметры экспорта — `output/render-report.json`. Для декодирования и проверки всех кадров нужен Python с `opencv-python-headless` и `numpy` (установить в отдельное окружение при отсутствии):

```powershell
python scripts/verify-outro.py
```

Результат — `output/verification.json`, реальные первый и последний кадры видео — `output/first-frame.png` и `output/last-frame.png`. Подробности сцен и детерминированности — [src/scenes/outro/README.md](src/scenes/outro/README.md).

## Проверка

```powershell
npm.cmd run check

# Используется установленный Chrome.
$env:PITCH_BUILD = '1'
npm.cmd test
```

Тестам нужен свободный порт **5182**. Они запускают и останавливают собственный сервер; основной проект не используют. Если Chrome не установлен:

```powershell
npx.cmd playwright install chromium
$env:PLAYWRIGHT_CHANNEL = 'chromium'
$env:PITCH_BUILD = '1'
npm.cmd test
```

Без `PITCH_BUILD=1` тестируется dev-сервер; офлайн-проверка пропускается, поскольку её нужно выполнять по готовой сборке без Vite HMR.

Проверяются три целевых разрешения, читаемость и границы текстовых блоков, клавиатура, fullscreen, перезапуск и быстрые переходы, reduced motion, галерея, локальные ресурсы, работа управления после отключения сети и отсутствие ошибок консоли. Результат финального прогона — в `artifacts/test-results.json`; снимки — в `artifacts/screenshots/`.

Диагностический замер кадров находится в `artifacts/frame-timing.json`. Это измерение локального headless Chrome, не гарантия частоты кадров на проекторе или другом компьютере. Firefox, Safari и физический проектор отдельно не проверены. Звука и экспорта в PowerPoint нет; доступны HTML-презентация и MP4-финал.

Проверка 17.10.2026: **15 passed, 0 failed, 0 skipped** на production-сборке в Chrome. `npm run check` прошёл для презентации и основного JanaМен. Сводка — `output/qa-report.json`, полный прогон — `artifacts/test-results.json`; проверка самого видео — в `output/verification.json`. Проверки ролика включают одинаковые кадры после перемотки, реальное воспроизведение 30 секунд, порядок подтверждения решения, управление, reduced motion и офлайн-работу после загрузки. Исходники основного JanaМен, backend, зависимости и Docker Compose этим заданием не меняются.

Анимации используют [GSAP context для очистки](https://gsap.com/docs/v3/GSAP/gsap.context()/) и [MotionPath для движения сигнала](https://gsap.com/docs/v3/Plugins/MotionPathPlugin/).
