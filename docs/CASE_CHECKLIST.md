## Границы и правила кейса

| | Правило | Как соблюдено |
|---|---|---|
| ✅ | Официальные кадровые данные read-only | В `zup_*` пишет только seed. Изменений профиля в API нет (`test_no_endpoints_to_change_official_data`). Отпуск уходит приказом в Documentolog |
| ✅ | Mock 1С:ЗУП и Documentolog, способ интеграции описан | `integrations/zup` (`ZupPort`), `integrations/documentolog`, `docs/ARCHITECTURE.md` |
| ✅ | AI не принимает кадровых решений | AI только отвечает; решения принимают люди или политики HR |
| ✅ | Чужие персональные данные без роли недоступны, проверка на бэкенде | `rbac` в каждом эндпоинте; зарплату видят только сам сотрудник и HR |
| ✅ | AI не придумывает правила и не раскрывает чужое | Порог уверенности 0.5, ответ только с источником, `NO_ANSWER`, 12 формулировок про чужие данные получают отказ без поиска |
| ✅ | Расширяемость | Порты `integrations/*`, реестр модулей, события, точки расширения профиля |
| ✅ | RU/KZ | Уведомления, ошибки (`messageKey`), курсы и ответы AI — ru/kk; все ext-экраны — переключатель RU/KZ, полнота словарей проверяется тестом (`23-ui-quality`). Экраны напарника — на русском |
| ✅ | Нет реальных ПДн, паролей, токенов, секретов | Seed вымышленный, ключи только в `.env`, в репо `.env.example`; проверено поиском по репо |
| ✅ | Явно: реализовано / смоделировано / развитие | `backend/README.md` |
