# Финальная проверка перед защитой (17.10.2026)

Ветка `feature`. Правило: каждый баг сначала ловится тестом, потом исправляется, потом PR.
Классы: **критичный** — ломает демо или сценарий кейса, утечка данных, падение; **серьёзный** — неверные данные, сломанный экран, обход прав; **мелкий** — тексты, вёрстка, косметика.

**Итог: критичных багов не найдено. 9 серьёзных найдено и исправлено (QA-01…09). Мелкие собраны в конце и ждут решения Даниила.**

## 1. Чистая установка, как у жюри

Чистый клон `feature` в новую папку, без кэшей и `.env`, по README буквально.

| Проверка | Результат |
|---|---|
| `docker compose build --no-cache` | 35 с |
| `docker compose up` → API и фронт отвечают | 52 с (с кэшем образов — 64 с, включая `npm ci` в контейнере) |
| Миграции 0001–0010 и seed | применяются сами, `/docs` и фронт — 200 |
| Окончания строк | `.gitattributes`: `* text=auto eol=lf` — CRLF на Windows не сломает скрипты |
| Абсолютные пути, файлы вне репо | нет |
| `.env` | необязателен (`required: false`), значения по умолчанию рабочие; `.env.example` содержит всё |
| Занятые порты 5432/8000/5173 | **было:** жёсткие порты, на Docker Desktop/Linux `up` падает. **Стало:** `DB_PORT/API_PORT/WEB_PORT`, CORS и адрес API следуют за ними; проверено на 5433/8001/5174 (PR #32) |
| README | **было:** корневой README начинался с `npm run dev` — это режим моков. **Стало:** первым идёт блок «одна команда `docker compose up`» (PR #32) |

Требование: Docker Compose ≥ 2.24 (синтаксис `env_file: required: false`).

## 8. Безопасность

- Матрица доступа: `test_qa_access_matrix.py` + smoke (403 для чужих данных за каждую роль, без лишних полей и зарплат). Через UI: чужой профиль, разделы HR, анонимность.
- Секреты: в дереве и во всей истории коммитов нет ключей, паролей, токенов; `.env` в `.gitignore` (кроме `.env.example`).
- Ответы с ошибками: только `{kind, code, message, messageKey}`, без стектрейсов и SQL.
- Ввод: HTML и `<script>` в комментарии к отпуску, обращении, вопросе AI, правиле базы знаний показываются текстом и не выполняются; `innerHTML` в коде нет (`24-input-safety.spec.ts`).

## Если на демо что-то упадёт

1. **Данные «уехали»** (кто-то нажал не то) — кнопка **DEMO → «Сброс данных»**: 1–2 с, всё как в seed.
2. **Белый экран или «Сервер недоступен»** — `docker compose restart backend`, через ~10 с обновить страницу.
3. **Фронт не открывается** — `docker compose restart frontend`; если порт занят — `WEB_PORT=5174 docker compose up`.
4. **Совсем плохо** — `docker compose down -v && docker compose up`, ≈ 1,5 мин до готовности.
5. **Запасной показ** — скриншоты всех шагов: `docs/screenshots/case/` (кейс) и `docs/screenshots/` (фичи).
