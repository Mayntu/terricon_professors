# Mock-система JanaМен

`createMockServices` реализует контракты auth, profile, leave requests и notifications.
Подключение — только `app/providers/AppProviders.tsx`; продуктовые страницы не
импортируют mocks и не обращаются к localStorage напрямую.

## Состояние

- `seed.ts`: вымышленные пользователи и профили; начальный реестр пустой.
- `demo-session.ts`: Employee / Manager / HRAdmin в sessionStorage отдельной вкладки.
  При недоступном sessionStorage роль живёт в памяти до reload. Это не авторизация.
- `store.ts`: одно versioned-состояние `jana.mock-state.v1` в localStorage.
  Заявка, событие решения и уведомление фиксируются одним setItem. Если запись
  не удалась, сервис возвращает unavailable и не сообщает об успехе.
- `state-validation.ts`: runtime-проверка формата сохранённого JSON. Несовместимые
  и повреждённые данные не затираются автоматически.
- Web Locks сериализует read–modify–write между вкладками современного браузера.
  Без него гарантируется только последовательная работа одной вкладки.
  `storage` events и revision подписки обновляют все открытые UI.

## Правила демонстрации

Лимит — 24 календарных дня включительно, без законов, праздников, начислений и
кадровой политики. Approved уменьшает тестовый остаток, Submitted его не резервирует.
На отправке проверяются календарные даты, порядок, прошлое начало, лимит, пересечения
Submitted/Approved и комментарий до 1000 символов. `submissionKey` предотвращает
дубликат одной отправки. UUID служит внутренним ID, последовательный JL-номер — видимым.

Manager видит и решает заявки собственной команды. Проверяются и managerId заявки,
и текущий руководитель в EmployeeProfile, а также роль и запрет согласовывать своё.
Только Submitted → Approved/Rejected, версия должна совпасть. Rejected требует
непустую trimmed-причину; Approved повторно проверяет тестовый остаток. Терминальные
заявки не принимают новое решение. Каждое решение создаёт ровно одно событие и
одно уведомление владельцу; отметка о прочтении также сохраняется.

Это моделирование инвариантов будущего API, а не безопасная авторизация. Данные
видны и редактируемы в DevTools. Сброс демо — явное удаление только `jana.mock-state.v1`
в DevTools и reload; другие данные браузера трогать не нужно. Искусственных задержек нет.

Проверки: `tests/mock-services.spec.ts` и `tests/leave-flow.spec.ts`.
Воспроизводимый сценарий показа описан в корневом README.
